# LEARNINGS — dashboards

- **No tests cover Lovelace YAML (2026-10-15).** `tests/` only scans `packages/` and HA's config check ignores dashboards. Before deploy: resolve every `!include`, check decluttering `variables` keys against the template's `[[...]]` tokens, and check entities against a live state dump.
- **`kohbo_device_door_entity` handles groups and single sensors.** It counts open members from the group's `entity_id` attribute and falls back to the entity itself; until 2026-10-15 single sensors always read "Closed".
- **Register new pages in `kohbo/kohbo.yaml` `views:`**, or the route doesn't exist. `room_card`'s `room:` is an HA area_id (compared to `sensor.<person>_room_presence`); a room with no HA area of its own (mudroom bathroom) gets a value that never matches, rather than the parent area's id, which would show that area's people.
- **Rooms with no temperature or air sensors omit the climate card** rather than leaving `climate_overview` slots empty or graphing an unavailable sensor (mudroom bathroom, 2026-10-16).
- **The small-bathroom pages stay separate (powder room, 2026-10-16).** Mudroom Bathroom and Powder Room differ in shape (brightness feature, toggle count, Sensors section), and decluttering-card can't drop list items, so a shared template would only wrap existing ones. Extract one if a third small bathroom page arrives.
- **An empty `!include` in `views:` becomes a blank view (holidays, 2026-10-16).** HA loads a 0-byte include as `{}`, so the view has no path and only exists at its numeric index (`/dashboard-kohbo/42`); links to the path it was meant to have are dead. Fill or remove the file, never leave it empty.
- **An Ecowitt WH51 that stops reporting holds its last value, often `0`, instead of going unavailable (plants, 2026-10-16).** Detect a dead channel by value: the plant cards show the graph on `numeric_state above: 0` and the Offline tile on `not` of that same condition, so the two are exact complements.
- **`kohbo_apexcharts_transparent.yaml` has one consumer (Lawn vs Rain, 2026-10-16).** It's a documented exception to "two uses = a template": it keeps inline `style:` out of the new view. The older apexcharts cards (`air_quality.yaml`) still carry the same block inline; switch them over when they're next edited.
- **The frontend never sees `last_reported` (sensors, 2026-10-16).** HA's compressed state feed sends only `lc` and `lu`, and reloads bump `last_updated` on everything, so "offline since" reads `last_changed`.
- **auto-entities `options` don't apply to `filter.template` output (sensors, 2026-10-16).** Template items are used as-is, so emit full row objects (`entity`, `type`, `template`) through `| tojson`. Keep JSON `true`/`false`/`null` out of them: HA parses template results with `literal_eval`, which rejects those and hands auto-entities a string that it splits on whitespace.
- **auto-entities' `group:` filter needs old-style `group:` (sensors, 2026-10-16).** Like `expand()`, it reads the `entity_id` attribute, which `platform: group` entities don't publish.
- **The Sensors page tracks what the room pages use (sensors, 2026-10-16).** Its groups in `packages/system/sensor_health/key_sensor_groups.yaml` were derived from `kohbo/rooms/**`, one entity per device. When you add a sensor to a room page, add it to the matching group too, or the Sensors page won't see it go offline.
- **`kohbo_security_overview.yaml` is a card, not a template, yet it sits in `button_cards/` (device health, 2026-10-16).** That directory is loaded with `!include_dir_merge_named`, so its `type:` and `cards:` keys become two junk button-card templates. Put whole-card includes under `templates/includes/` instead, as `includes/sensors/device_health_overview.yaml` does.
