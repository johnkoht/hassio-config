# LEARNINGS — packages/holidays

- **Z-Wave re-inclusion renames plugs (2026-10-15).** Moving the front yard plugs to the ZWA-2 dropped the `_1` suffix (`switch.front_door_smart_plug_1` → `switch.front_door_smart_plug`). A multi-entity `state` condition needs *every* entity to match, so one dead ID silently blocked the Halloween automations all season. Use any-on/any-off template conditions, and check live IDs after any controller migration.
- **The front yard Hue power plugs stay out of automations.** `switch.front_yard_outdoor_front_left_hue_lights` (+ `_2`) power the Hue spots and must stay on; the spots are driven by `outdoor_lighting.yaml` and `halloween_hue_scene.yaml`, which applies the HA scene `scenes/holidays/halloween_front_yard_spots.yaml`. That covers spots 11–14 as well; the Hue app's Front Yard scene doesn't.
- **Plug IDs live only in `front_yard_holiday_decorations.yaml`.** Halloween and Christmas target `switch.front_yard_holiday_decorations`; fix a rename there, nowhere else.
- **`switch.christmas_lights` contains the front yard group (2026-10-16).** It reads On during Halloween, and turning it off kills the Halloween decorations. The Holidays page hides it out of season; the group itself is unfixed (see [the Holidays dashboard README](../../dashboards/kohbo/holidays/README.md#caveats)).
- **`deploy.sh --reload` doesn't reload groups or scenes.** A new `platform: group` switch needs Developer Tools → YAML → Groups, and a new scene file needs Scenes.
- **Gate `homeassistant start` triggers by time of day (2026-10-17).** An ungated startup trigger turned the decorations off at a daytime restart. Give the trigger `id: startup` and an `or: [not trigger startup, <time window>]` condition, so a restart re-applies the state the hour calls for (`halloween_lights.yaml`). Christmas still has the old pattern.
