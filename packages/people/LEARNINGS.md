# LEARNINGS — packages/people/

- **Commute station zones are private.** Reference them only as `!secret commute_{home,midway,city}_station_zone` and keep file names, ids and aliases generic. Speak the real name at runtime with `trigger.zone.attributes.friendly_name`. `tests/test_commute_regressions.py` enforces this.
- **Don't match a person's state against a zone's friendly name.** That puts the name in the repo. Use `condition: zone` (it takes a list and ORs it). To keep a "held for N minutes" trigger, use `trigger: state` with `to: ~` plus `for:`, then check the zone in the conditions.
- **The turn_on/turn_off chains target alias-derived entity ids**, e.g. `automation.john_arrived_at_home_station`, not the `id`. Renaming an alias breaks the chain, and the test catches it.
- **A helper with no `initial:` reads its minimum, so "unset" needs its own value (medication stock, 2026-10-30).** `input_number.nino_medication_stock` has `min: -1`; the days sensor is `unavailable` below 0, so an unseeded count is silent instead of looking like "0 left". Guard writes that would turn -1 into 0: the refill and set scripts stop when days is not above 0, and the decrement needs stock above 0.
- **Decrement with `input_number.decrement`, not read-then-`set_value`.** It is atomic and clamps at min; pair it with a `numeric_state above: 0` condition because min is -1 here. Trigger only `from: "off"` `to: "on"` so the 03:00 reset and restart restores never count.
- **Only core helper reloads are needed.** `input_number.reload` and `template.reload` exist, so new helpers do not need a restart.
