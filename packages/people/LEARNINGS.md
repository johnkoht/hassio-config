# LEARNINGS — packages/people/

- **Commute station zones are private.** Reference them only as `!secret commute_{home,midway,city}_station_zone` and keep file names, ids and aliases generic. Speak the real name at runtime with `trigger.zone.attributes.friendly_name`. `tests/test_commute_regressions.py` enforces this.
- **Don't match a person's state against a zone's friendly name.** That puts the name in the repo. Use `condition: zone` (it takes a list and ORs it). To keep a "held for N minutes" trigger, use `trigger: state` with `to: ~` plus `for:`, then check the zone in the conditions.
- **The turn_on/turn_off chains target alias-derived entity ids**, e.g. `automation.john_arrived_at_home_station`, not the `id`. Renaming an alias breaks the chain, and the test catches it.
- **A helper with no `initial:` reads its minimum, so "unset" needs its own value (medication stock, 2026-10-30).** `input_number.nino_medication_stock` has `min: -1`; the days sensor is `unavailable` below 0, so an unseeded count is silent instead of looking like "0 left". Guard writes that would turn -1 into 0: the refill and set scripts stop when days is not above 0, and the decrement needs stock above 0.
- **Decrement with `input_number.decrement`, not read-then-`set_value`.** It is atomic and clamps at min; pair it with a `numeric_state above: 0` condition because min is -1 here. Trigger only `from: "off"` `to: "on"` so the 03:00 reset and restart restores never count.
- **Only core helper reloads are needed.** `input_number.reload` and `template.reload` exist, so new helpers do not need a restart.
- **Home presence no longer uses iPhone Detect or nmap (2026-11-07).** HA runs on the Servers VLAN, away from the phones. The MQTT tracker on the phones' VLAN publishes the same `device_tracker.*_iphone_detect` ids, so persons and Bayesian sensors needed no change; nmap is commented out of the Bayesian inputs. Tracker state isn't retained, so it reads `unknown` for about 12 s after a restart.
- **Departure announcements hold 1 minute (JK-1242).** A GPS flap at the zone edge (leave → enter → leave within 27 s) announced a departure twice. Every `*_announce_departure` trigger now has `for: minutes: 1` (and an explicit `to:`). Only the announcement waits; the away/home state, `Just Left` and house occupancy are not delayed. `tests/test_departure_debounce.py` covers it.
- **UniFi trackers blip home on a WLAN toggle (2026-11-11).** Switching the kids WLAN off briefly marked four offline clients home for about 9 minutes, Katia's phone among them. `katia_is_home` now requires `device_tracker.katia_iphone_detect` = home, which fails closed: if the MQTT tracker is down, she is never marked home, and the BLE `device_tracker.see` assist can't help.
- **A UniFi blip drives person.* directly, so gate every consumer, not just the home boolean (JK-1251, 2026-11-13).** Tayta's UniFi tracker flipped home 70 min after she left while `sonia_iphone_detect` stayed away; the arrival announcement, guest mode and the garage unlock all trigger on `person.sonia_koht`, not on `input_boolean.tayta_home`. The parents' arrival announcements and the garage unlock now wait `for: 1 minute` and require their detect tracker (detect trails UniFi by 4-20 s on a real arrival). Cleaner root fix, if wanted: drop the UniFi tracker from the parents' persons (UI config).
- **A room-presence template going `unavailable` is a state change.** `template.reload` flipped `sensor.tayta_room_presence` not_home -> unavailable and `from: not_home` fired `tayta_is_home`. Use `not_to: [unavailable, unknown]` on state triggers and `not in ['not_home','unavailable','unknown']` in templates (a bare `!= 'not_home'` is true for unavailable).
