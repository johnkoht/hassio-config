## Orchestrator adjudication (2026-11-25)

- **#1 downgraded from CRITICAL to HIGH, with evidence from the live host.** The installed `homeassistant/components/lovelace/dashboard.py` does `from homeassistant.util.yaml import Secrets, load_yaml_dict` (line 19) and calls `load_yaml_dict(self.path, Secrets(Path(self.hass.config.config_dir)))` (lines 257-259). So YAML-mode dashboards do resolve `!secret`, and the loader passes secrets on to `!include`d files.
  - **The real risk:** the two keys are missing from the host `secrets.yaml` today. An undefined secret fails the whole dashboard.
  - **Mitigation:** add `john_ha_user_id` and `cristina_ha_user_id` to the host `secrets.yaml` before deploy (values from `.storage/auth`, never printed). Then load `lovelace/config` over websocket and confirm the views render. Placeholders go in `secrets.fake.yaml`.
- **#2 accepted:** drop the helper fallback. If `!secret` does fail, the fallback is the button-card JS comparison against `person.*` `user_id`.
- **#3, #4, #5, #7 and #10 accepted as written,** and folded into the PRD acceptance criteria.
